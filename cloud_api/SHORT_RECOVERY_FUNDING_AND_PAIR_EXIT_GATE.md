# SHORT Recovery 2.0 — proven evidence boundary (offline)

Reviewed on 2026-10-17 against `aster_gateway.py`, `short_recovery_funding_shadow.py`, and `short_recovery_order_resolution_shadow.py`.

## Funding
- `AsterV3Client.income_history()` requests `/fapi/v3/income` using `symbol`, optional `incomeType`, timestamp range and `limit`. This wrapper does **not** expose a stable income transaction ID cursor.
- A full timestamp-bounded income page cannot prove completeness where multiple income events share one millisecond. `income_pages()` correctly refuses a full page rather than guessing a continuation.
- A funding row's symbol/time (and even an optional side) does not prove which price-zone allocation and hedge cycle owns the transaction. `funding_for_cycle()` requires independently evidenced `tranId` -> (symbol, side, cycle) ownership for *every* funding event.
- Consequently the existing exchange adapter cannot currently certify full net profit for overlapping hedge cycles based solely on Aster income and userTrades responses. Missing evidence remains unknown, never a synthetic zero. No settlement or live GO is justified by this document.

## Partial pair close
- The canonical `resolve()` keeps an already filled but then terminally cancelled order in `PARTIAL_TERMINAL`, preserving the claim and inventory for reconciliation, rather than releasing another order.
- A `CANCEL_TERMINAL` applied after any fill now additionally requires explicitly verified terminal readback and a matching Aster order ID. This verifies the supplied *mock* evidence contract, not authenticity against the exchange in production.
- No automatic residual LONG/SHORT order is authorized. Complete both-side exchange reconciliation, risk checks and independent funding attribution before considering a pilot.

## Execution integration gate review (2026-10-17)
`aster_position_loss_auto_hedge_extension.py` invokes Recovery only under `not execute` and `ASTER_SHORT_RECOVERY_SHADOW_ENABLED=true`, after the existing reconciliation call. Thus the new atomic pair-settlement has no live executor caller and cannot govern live orders. Making it active would require (a) a canonical account/cycle-level order guard and persisted side claims shared by the existing Auto Hedge reconciler, (b) an authoritative desired-hedge transition avoiding legacy 1:1 top-up on intentional partial SHORT, and (c) pre-submit readback/stop checks and terminal settlement before any fresh order. Do not enable it without those invariants and a separately authorized live pilot.

Aster income_history's available parameters are symbol/type/start/end/limit, not an income ID cursor. Price-zone/cycle ownership is not present in that contract; two hedge cycles on the same symbol and side cannot be distinguished by these records alone. The current `funding_for_cycle()` accepts independently supplied transaction ownership, but exchange retrieval does not establish it. Inability to prove income completeness or attribution must fail closed; cannot claim net TP or live readiness.

## Verified local Aster gateway income contract — 2026-10-18
`AsterV3Client.income_history()` calls `GET /fapi/v3/income` with optional `symbol`, `incomeType`, `startTime`, `endTime` and `limit` (1–1000). It exposes no `tranId` pagination cursor, per-cycle identifier or price-zone-seat identity. Transactions from simultaneous cycles of the same symbol are not independently attributable using this API wrapper, and timestamp-only pagination cannot prove completeness at a full page's boundary. The deterministic client-order ID identifies order executions, not funding ownership. **Do not infer zero funding or distribute funding proportionally**; pair net TP stays NO-GO unless independently verifiable complete ownership evidence is obtained.

## Overlapping cycles are not made independent by zero SHORT seats
SHORT price-zone seats may be set to 0 by one user, but remain configurable. Auto Hedge can still create several SHORT hedges for separate LONG zone seats on the same symbol, so no exclusive exchange funding ownership follows from SHORT seat count. The Firestore canonical ledger and clientOrderId track distinct orders and cycle fills, whereas Aster `/fapi/v3/income` exposes neither a claim/cycle ID nor a sufficiently complete transaction-ID cursor in the current gateway. These records alone cannot independently certify the funding cost of each overlapping hedge. Continue to require external transaction-specific proof; otherwise block joint net TP, including when income records are empty.

## Symbol-level accounting design assessment (2026-10-18)
Conservative symbol-level accounting can safely establish a *symbol-wide* PnL result only when the entire symbol inventory and all its concurrent LONG/SHORT legs are treated as one indivisible accounting and exit scope, and every funding/fee/income event is complete. It cannot establish net profit for a single price-zone hedgecycle while other hedgecycles share that symbol. Restricting independent TP to one cycle would require independently exchange-proven exclusive position/transaction ownership and a complete transaction listing (no unresolvable full same-timestamp pages). Existing Aster `income_history` does not provide this evidence. Neither `shortSeats=0` nor a cycle/order ID attached to entries resolves funding attribution. DO NOT enable a symbol-wide forced close as a workaround, since unrelated legacy/Recovery legs might be closed. Keep per-cycle joint net TP fail closed; preserve all seat/ladders. A future account-opt-in *whole-symbol portfolio exit* would need a separate explicit authorization and complete bounded accounting contract, not an implicit fallback.

## Independent position/time exclusivity finding (2026-10-18)
Even if a ledger shows only one hedgecycle active in a given time interval, this is a local ownership assertion, not exchange-confirmed funding transaction ownership. The existing Aster gateway's `position_risk` reflects aggregated side exposure and its income API provides no hedgecycle/client-order mapping. A timeline snapshot also cannot exclude transient outside positions, out-of-band modifications, missing income rows, or identical-timestamp pagination gaps. Therefore time-only exclusivity must not be promoted to a proof map for `funding_for_cycle`; transaction-specific independent ownership and completeness remain mandatory. No change to seat settings or Recovery ladder defaults.

## Candidate solution — conservative per-symbol funding lower bound (offline only)
A possible safe alternative to dividing funding among overlapping cycles is to debit *every negative funding event for the entire symbol* against **each** candidate hedgecycle, and ignore all positive funding. This deliberately overstates costs and cannot invent net profit. The same conservative bound can be reused for several candidate cycles, but may prevent otherwise profitable exits. Crucial precondition: independently evidenced completeness of all symbol funding for the full cycle exposure interval, including resolved pagination boundaries. `conservative_symbol_funding_floor` calculates only the bound; its caller-provided coverage flags are not proof. Current Aster income/position APIs alone do not provide an independent completeness/ownership certificate. Thus this candidate is NOT integrated into TP authorization and is NOT live-ready. No symbol-level forced close or changes to LONG/SHORT seats or Recovery ladder settings.
